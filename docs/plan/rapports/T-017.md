# T-017 — Artisanat : GlobalState → abonnements de zone

`vava_crafting` 1.4.0 → 1.5.0, selon `docs/plan/specs/T-014.md` § 13.4. Core requis : 0.11.0 (`core.zones`). Aucun
fichier du core ni de `vava_gathering` / `vava_farming` touché.

## Ce qui change

| Sujet | Fait | Où |
|---|---|---|
| Zone par station | chaque station placée (config et `addStation`) est une zone du core nommée par son identifiant : cercle de 2 m, marge `streaming.radius` + `subscribeSlack` = 100 m ; déclarée au setup (`stations.declareAll`) et à l'ajout (`stations.adopt`) ; une déclaration refusée est écrite en console et retentée au changement suivant | `server/stations.lua`, `config.lua` (`streaming.zoneRadius`, `streaming.subscribeSlack`) |
| État de zone | `def` → `{ type, label, x, y, z, heading, prop }` (ni qualité ni propriétaire : rien de privé) ; `s` → `{ fuel, busy }`, envoyé au seul changement (`set`, ~34 o, regroupé par le core avec les autres changements du tour) | `shared/stationzone.lua`, `server/stations.lua` |
| GlobalState | plus aucune écriture ; `vava_crafting:station:<id>` et `vava_crafting:stations` effacées une fois au démarrage si présentes (ligne marquée `audit: ok`) | `server/stations.lua` (`forgetLegacy`), `shared/constants.lua` (`LEGACY_*`) |
| Évènement `vava_crafting:station` | retiré (combustible envoyé trois fois, MINEUR de T-011) : le menu ouvert suit le `s` de la zone, la réponse du RPC `fuel` reste | `server/crafting.lua`, `client/main.lua`, `client/interact.lua` |
| Client | `core.zones.watch` → carnet pur (`stationzone.book`) : `enter` / `change` / `leave` ; prop retiré quand une station bouge ou part ; plus de liste de config de repli ; **boucle des props seulement si une station est connue** (aucune boucle loin de tout) | `client/props.lua` |
| Station changée en jeu | `stations.share(def)` : `move` + `set` du dessin si déjà déclarée (prêt pour l'Atelier) ; ajout par un module → reçu au passage suivant (1 s), sans reconnexion | `server/stations.lua` |
| `addStation` | identifiant ≤ 32 o (`invalid_id`), position finie (`invalid_position`), nom chaîne 1–128 o (`invalid_label`), modèle chaîne 1–64 o (`invalid_prop`) : ce que le client accepte de dessiner. API publique gardée ; seul appelant : `vava_farming` (composteur), conforme | `server/catalog.lua`, `server/api.lua` |
| Distance | inchangée : `menu`, `begin`, `finish`, `fuel`, réparation revérifient la position lue par le serveur à chaque action, sans se fier à l'abonnement | `server/crafting.lua`, `server/repair.lua` |
| Sons | aucun son de station n'existe aujourd'hui ; consigne écrite (bridge, README, api.md) : `core.zones.subscribers(id)` ou `sendNear` | `bridge/server.lua` |

Tailles estimées (`netsize` du core) : état d'une station 170 à 194 o ; arrivée au bourg (7 stations) 1,26 Ko, une
fois ; une différence `s` 34 o aux seuls abonnés. Avant : 47 o par écriture d'état chez **tous** les joueurs (deux
par pièce au moins), liste de 944 o réécrite chez tous à chaque `addStation`.

**Cases de 128 m** : pas justifiées par l'artisanat. Cercle d'intérêt de 102 m → 1 à 4 cases de 256 m par station ;
8 zones au bourg, négligeables devant la voix, la récolte et l'agriculture. `zones.cellSize` laissé à 256 m ; à juger
avec les mesures en jeu de T-015/T-016.

## Hors périmètre (relevé)

- Le composteur (type déclaré par `vava_farming`) n'a pas d'invite chez le client : `props.type` lit
  `cfg.stationTypes` du client, qui ne connaît pas les types ajoutés par d'autres modules (comportement antérieur).
- Aucune API de retrait de station : une station retirée (Atelier, T-104) devra appeler `core.zones.remove`.
- `config.lua` (partagé) livre toujours la liste des stations au client ; le client ne s'en sert plus.
