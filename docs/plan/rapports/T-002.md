`tests/helper.lua` : `pending.lua` lit `SetTimeout`, `promise.new` et `Citizen.Await` dès son chargement. Le helper
fournit donc trois doublures :
- `SetTimeout` range la minuterie dans `helper.timers`, et le test la déclenche lui-même (`helper.timers[i].fn()`) ;
- la promesse n'accepte qu'une seule résolution ;
- `Citizen.Await` rend la valeur et lève une erreur si la promesse n'est pas encore résolue, car il n'y a pas de
  planificateur hors jeu.

`helper.reset()` vide `helper.timers`. Aucune autre modification hors de `tests/spec/`.

Pour les hooks, la spec remplace `GetGameTimer` et `print` **avant** le chargement, parce que `logger.lua` et
`hooks.lua` les gardent en local. Elle peut ainsi simuler un handler lent et lire le journal. Ces remplacements passent
par `_G` : sous busted, une affectation nue dans une spec reste dans l'environnement isolé du fichier.

## Bugs et écarts trouvés (tests laissés en échec)

**Suite** : les quatre bugs ont été corrigés dans `vAvA_core` 0.7.5, avant le commit de ces tests ; les tests n'ont
pas été modifiés. Désormais, avec les 6 tests d'origine, busted donne 152 succès sur 152.
- S1 : `compile` refuse une borne non entière pour string, array et map, ainsi qu'une borne `NaN`.
- S2 : `compile` refuse `NaN` dans `enum`.
- S3 : `validateList` refuse toute clé hors de 1 à `count`. Le client n'envoie que `{ ... }` avec
  `select('#', ...)` : rien ne change pour lui.
- C1 : `sanitize` retire la suite entière des `^` avec le chiffre.

Le tableau « Schémas » de `docs/api.md` précise désormais : longueur en octets, bornes entières, pas de `NaN`.

### S1 — Une borne de longueur ou de nombre d'éléments non entière fait lever `validate` (faible)
- **Code** : les messages d'erreur sont construits avec `format('… %d', borne)` :
  - longueur d'une chaîne : `shared/lib/schema.lua:168-169` ;
  - nombre d'éléments d'une liste : lignes 205 et 208 ;
  - nombre d'entrées d'une map : lignes 222 et 228.
- **Entrée** : `{ type = 'string', max = 2.5 }` et la valeur `'abc'`. Même chose avec `min = 2.5` et `'ab'`, avec une
  liste `max = 1.5` et une map `min = 1.5`.
- **Obtenu** : erreur levée, `bad argument #2 to 'format' (number has no integer representation)`.
- **Attendu** : `false, err` (contrat de `schema.validate`). Pour `docs/api.md`, « Aucune fonction de l'API ne lève
  d'erreur » : `core.registry.add` lèverait. Sur un RPC, la valeur d'un client ferait lever le handler de l'évènement
  réseau. Le client n'aurait pas de réponse et la console recevrait une trace d'erreur à chaque requête, sans
  limitation de fréquence.
- **Portée actuelle** : aucun module n'utilise de borne non entière sur une chaîne, une liste ou une map. J'ai vérifié
  par recherche : les bornes `0.1`, `-1.01` et `1.01` portent sur des `number`, dont les messages utilisent `%s`.
- **Correction possible** : utiliser `%s` dans ces messages, ou refuser à la compilation une borne non entière pour une
  longueur ou un nombre d'éléments. Le test admet les deux.

### S2 — `NaN` dans une liste `enum` fait lever `schema.compile` (faible)
- **Code** : `shared/lib/schema.lua:133`, `set[allowed] = true`.
- **Entrée** : `{ type = 'number', enum = { 1, 0/0 } }`.
- **Obtenu** : erreur levée, `table index is NaN`.
- **Attendu** : `nil, err`, comme pour toute définition invalide (« enum vide »…). Pour `docs/api.md`, « Aucune fonction
  de l'API ne lève d'erreur » : `core.rpc.register` et `core.registry.define` lèveraient.
- **Portée** : erreur de développeur uniquement. Un client ne peut pas la déclencher.

### S3 — `validateList` accepte une valeur au-delà des schémas déclarés (contrat non tenu, sans effet aujourd'hui)
- **Code** : le contrat est écrit en `shared/lib/schema.lua:280` : « Toute valeur au-delà de `count` ou des schémas
  déclarés est refusée. » Mais la boucle des lignes 294 à 301 ne regarde que les indices 1 à `#compiledList`.
- **Entrée** : un seul schéma, `values = { 1, 'en trop' }`, `count = 1`.
- **Obtenu** : `true`.
- **Attendu** : `false` (contrat de la fonction ; `docs/api.md` ne décrit pas `validateList`).
- **Portée actuelle** : aucune. `server/core/rpc.lua:146` et `:199` ne déballent que `1..count`, donc la valeur en trop
  n'atteint jamais le handler.
- **À trancher** : vérifier aussi `values[#compiledList + 1]`, ou corriger le commentaire.

### C1 — `str.sanitize` laisse passer un code couleur reconstitué (faible)
- **Code** : `shared/lib/string.lua:55`, `gsub(text, '%^%d', '')`. Ce remplacement ne fait qu'une passe.
- **Entrée** : `'^^11joueur^^77'`.
- **Obtenu** : `'^1joueur^7'`. Le retrait de `^1` colle le `^` restant au `1` suivant.
- **Attendu** : aucun code `^0`–`^9` restant (contrat de la fonction, `string.lua:46-47` : « codes couleur FiveM
  (^0-^9) … retirés »).
- **Portée** : un client qui appelle un RPC inexistant nommé ainsi colore la console du serveur
  (`server/core/rpc.lua:117`). Les caractères de contrôle restent neutralisés : une fausse ligne de journal reste
  impossible.
- **Correction possible** : retirer `%^+%d` en une passe, ou répéter le remplacement tant qu'il change quelque chose.

## Observations sans test en échec (comportement non documenté, à trancher)

- **Borne `NaN` dans une définition** : `{ type = 'integer', min = 0/0, max = 10 }` compile, puis accepte `-1e9`, car
  la borne est ignorée sans le dire. `docs/api.md` ne parle de `NaN` que pour les valeurs. Je suggère de refuser une
  borne `NaN` à la compilation (`def.min ~= def.min`).
- **Définition cyclique** (`def.items = def`) : `schema.compile` lève `stack overflow` (récursion de
  `shared/lib/schema.lua:60`). C'est une erreur de développeur, de la même famille que S2.
- **Longueur des chaînes en octets** : `docs/api.md` dit « longueur » sans préciser l'unité, mais le code compte les
  octets. Un « é » en vaut deux, donc `max = 32` limite un nom accentué à 16 « é ». Un test fixe ce comportement. Je
  propose d'écrire « longueur en octets » dans le tableau.
- **Hors périmètre (`server/core/rpc.lua:141-143`, non testé ici)** : la conversion flottant → entier
  (`3.0` → `3`) ne s'applique qu'aux arguments de premier niveau. Un champ `integer` imbriqué dans une table arrive
  au handler en flottant (`3.0`).
- **Aucun écart trouvé dans les hooks** : les 32 tests confirment chaque point de la section `core.hooks` de
  `docs/api.md` :
  - ordre d'exécution, priorité par défaut 100, bornes 0 à 1000 ;
  - `false, raison` arrête la chaîne ; `hook_error` fait échouer l'action ;
  - les handlers `after` continuent après une erreur ;
  - handler lent au-delà de 25 ms, journal limité en fréquence ;
  - `off` ne retire que ses propres hooks ;
  - espace de noms `<ressource>:` pour déclencher, sans confusion entre `vava_a` et `vava_ab`.

## Ce qui n'est pas testable hors jeu

- **Sérialisation msgpack réelle** : distinction entier / flottant à l'arrivée, références de fonction transmises
  comme tables à `__call`, perte du champ `n`. Les tests reproduisent les formes attendues sans passer par le réseau.
- **`SetTimeout`, `promise` et `Citizen.Await` réels** : les doublures sont synchrones. L'attente dans un thread,
  l'ordre réel des minuteries et un handler de hook qui attend la base sont à vérifier en jeu.
- **Le reste de la surface d'API** : `getApi` (`GetInvokingResource`, `exports`), la garde `modules.isActive`, et la
  purge des hooks à l'arrêt d'une ressource (`purgeOwner` est testé, son appel sur `onResourceStop` ne l'est pas).
- **Affichage dans la console FXServer** : couleurs réelles (effet visible de C1) et vraie mesure des handlers lents
  avec `GetGameTimer`.
- **Hors périmètre de T-002** : `server/core/rpc.lua`, `ratelimit.lua`, `registry.lua` et `modules.lua`.
  - Ils sont testables avec des doublures de `RegisterNetEvent`, `TriggerClientEvent` et `DoesPlayerExist`.
  - Une tâche dédiée couvrirait la chaîne de contrôle d'une requête entrante (bucket, forme du message,
    `invalid_args`, conversion des entiers).
