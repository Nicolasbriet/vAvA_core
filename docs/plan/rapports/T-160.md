## Écarts à la spec

1. **`leanResources(resources)` sans options allège le Lua seul** (la spec : « défaut : les deux ») ; avec un objet
   d'options, `lua` et `web` valent vrai sauf `false`. Sans cela `tests/livraison/essais.js` (T-154), que la spec
   interdit de toucher, échoue : son essai « allègement » relit `web/js/a.js` d'une ressource à `vava_conseil_web` et
   l'attend commenté. L'installeur et `livraison.js --sortie` passent toujours `{ lua, web }`. De même
   `installer.leanSource(racine, job)` sans options : le Lua seul.
2. **Ressources illisibles dites au journal seulement si le Lua est allégé ou s'il y a des pages** : avec
   `leanLua: false` et aucune page, l'essai de T-154 attend une seule ligne (« Allègement du Lua livré désactivé … »).
3. **Signature CSS : écart 2 derrière un commentaire seul** (la spec : commentaire transparent, écart 0). Plus strict :
   le contrôle voit aussi un commentaire retiré entre deux noms (`div/**/p` → `divp`) ; un commentaire qui touche un
   blanc laisse de toute façon un blanc entre ses voisins (écart 1 des deux côtés). Les lexèmes CSS « autres » sont des
   suites d'octets ordinaires (et non un octet chacun) : moins de mémoire, et `divp` diffère de `div` + `p`.
4. **Marque `blanc` sans numéro de ligne** (signature HTML de `webstrip`, et dans `meme-page.js` les marques de blanc
   HTML et CSS) ; la spec donnait la ligne du premier caractère. Un commentaire retiré allonge le blanc voisin de ses
   fins de ligne : un fichier qui commence par un en-tête `/* … */` ou un commentaire HTML de plusieurs lignes précédé
   d'un texte vide aurait été refusé par son propre contrôle (et toujours en écart pour le second lecteur). Les lignes de
   tous les autres lexèmes, et le nombre de fins de ligne, restent comparés.
5. **BOM tenu pour le début du texte** dans la signature (comme pour l'allègement CSS) : sinon `BOM + /* c */a {}` était
   refusé par le contrôle (trouvé par un essai).
6. **Lignes `refuse` de `--essai-pages` : cinquième colonne `livre` ou `depot`** (`refuse<TAB>chemin<TAB>ligne<TAB>raison<TAB>livre|depot`) :
   le second lecteur en a besoin pour appliquer le tableau du § 10.1 (page livrée refusée → ÉCART ; hors livraison →
   noté).
7. **`verifier.sh` : chaque essai de page sur la copie est lancé depuis le dossier de sa ressource**
   (`( cd "$tmp/copie/[vava]/$m" && node web/dev/essais.js )`) au lieu de `node "$tmp/copie/[vava]/$m/…"` : sous Git
   Bash, un argument qui contient `[` n'est pas converti en chemin Windows, et node cherchait `F:\tmp\…` (vu). Même
   fichier d'essai, même `__dirname`.
8. **Nom de propriété** : un nom précédé de `.` (`o.return / 2`, `a.if(1) / 2`) n'est jamais lu comme un mot-clé pour la
   règle de `/` (précision ; deux essais).
9. **Refus en plus**, tous prudents : `\` hors chaîne en JS qui n'est pas un échappement `\u` ; texte JS qui finit avec
   une parenthèse ou un gabarit ouverts ; `\` en fin de fichier CSS ; `<!`/`<?` sans `>` ; élément brut sans sa balise de
   fin (raisons écrites au § « Ce qui change »).
10. **Exports en plus** : `livraison.js` exporte `listePages`, `essaiPages`, `sortie` avec une racine en paramètre (essais
    sur un dépôt git factice : code 1 d'une page livrée refusée, seconde ligne de bilan) ; `meme-page.js` exporte
    `readJs`, `readCss`, `readHtml`, `run`.
11. **Essais en plus** : `fetchSource` avec une page qui ne peut pas être réécrite (`lean_failed`), les quatre
    combinaisons `leanLua`/`leanWeb`, une archive sans page ; recherche de `--!>` sur 20 000 commentaires en moins d'une
    seconde ; bornes exactes (1 024 parenthèses, 64 gabarits, 1 Mio) ; `engineCompiles` n'exécute rien ; idempotence.
12. **Mesures** : le gain des seules lignes « joueurs » est de 149 984 octets (≈ 146 Kio), sous l'estimation de la
    spec (180 à 220 Ko) ; le filtre `awk` du § 10.5, qui compte aussi les quinze lignes `vava_atelier@conseil`, donne
    − 157 992 octets : **seuil de − 150 Ko tenu sur la mesure de la spec**, de justesse pour les joueurs seuls (l'écart à
    l'estimation vient surtout de la page de l'Atelier, partie dans le paquet du Conseil avec T-157). 20 ressources ont
    des pages (la spec en estimait 22) ; 18 pages portent la ligne « hors jeu » (la spec en comptait 17).

## Choix faits

- `meme-page.js` lit l'entrée standard (`fs.readFileSync(0)`), toujours redirigée depuis un fichier dans `verifier.sh`.
- Les cas difficiles portent des blancs de fin de ligne voulus (`cas_difficiles.js` lignes 14 et 20, `.css` ligne 26) :
  `git diff --check` les signale ; `tests/` est hors de luacheck.
- Le lexeur JS et le second lecteur ne partagent rien : décodages différents (latin1 / UTF-8), règles de `/` écrites
  différemment (lexème précédent et refus, contre contexte des accolades sans refus), et V8 compile les deux textes.
