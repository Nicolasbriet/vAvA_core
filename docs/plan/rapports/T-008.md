- **Arrêt de `vava_voice`** : aucun micro n'est plus rendu à l'arrêt. Un `restart` laisse donc muets les joueurs en

## Relecture

Relecture indépendante : sécurité OK, réseau OK. Suites appliquées dans un commit à part, versions inchangées
(Chancellerie 1.4.2 et `vava_voice` 1.2.1 ne sont pas encore publiées).

| # | Point relevé | Suite |
|---|---|---|
| 1 | `exec` non vu, ligne insérée qui l'écrase ; `;` | `analyzeRequired` (`chancellerie/lib/servercfg.js:291`) : une ligne `exec` active, ou une ligne à plusieurs commandes (`;` hors guillemets, `segments` `:249`) qui touche la voix ou cache un `exec`, rend le fichier douteux : rien n'est écrit, avertissement en console et au journal (« server.cfg à vérifier (voix) », `index.js:92`). |
| 2 | `set`, `sets` comptés comme `setr` | Seul un `setr` compte comme posé ; un `set`, un `sets` ou une convar nue n'est jamais doublé et donne « remplacez set par setr » ; l'autre réglage, s'il manque, est ajouté. L'assistant (`generate`) garde sa règle : rien en double. |
| 3 | Encodage | Lecture en Buffer ; aller-retour Buffer → texte → Buffer différent : `{ error: 'encoding' }`, rien d'écrit (`completeNow`, `:369`) ; BOM retirée puis remise en tête ; fins de ligne gardées ligne par ligne (`splitLines`, `:268`), les lignes ajoutées prennent celle de leur voisine. |
| 4 | Écriture sans action humaine | `write` (`:486`), pour **toutes** les écritures (assistant, éditeur brut, lancement au démarrage, restauration, voix) : `accessSync(W_OK)` d'abord ; lien symbolique suivi (`realpathSync` : la cible est écrite, le lien reste) ; temporaire au nom unique, `flag: 'wx'`, droits de l'ancien fichier ; puis copie de l'ancien dans les sauvegardes, renommage ; en cas d'échec, temporaire et copie de ce tour supprimés ; rotation des sauvegardes après un succès seulement (`rotateBackups`, `:458`). Un fichier inchangé (date de modification, taille) depuis un échec ou un avertissement n'est ni retenté ni réinscrit au journal (`lastProblem`, `:360`). |
| 5 | Nom de zone | `vava_voice/shared/label.lua:21` : contrôles C1, largeur nulle, marques de sens d'écriture (U+200B–U+200F, U+2028–U+202E, U+2066–U+2069) et BOM refusés ; U+00A0 compte comme une espace pour le nom vide (`:50`) et reste permis ailleurs. Tests ajoutés. |
| 6 | Doc de l'arrêt | README de `vava_voice` et voix 8-5 : `stop` sans redémarrage ou setup en échec, joueurs en sélection muets jusqu'à leur reconnexion. |

Deux écarts assumés, à faire valider :
- **Sauvegarde** (point 4) : la copie de l'ancien fichier est prise **après** l'écriture réussie du temporaire mais
  **avant** le renommage, puis retirée si le renommage échoue. Prise après le renommage, comme demandé à la lettre, un
  arrêt brutal entre les deux laisserait l'ancien contenu (secrets compris) sans aucune copie. Sur un échec, le
  résultat est celui demandé : ni sauvegarde ni rotation, temporaire supprimé.
- **Fichier inchangé après un échec** : la clé est la date de modification et la taille, comme demandé. Rendre le droit
  d'écriture sans toucher au fichier ne provoque donc un nouvel essai qu'au prochain lancement de la Chancellerie (la
  console le dit). J'avais essayé d'y ajouter la date de changement d'état : sous Windows, elle n'a pas suivi le
  retrait de la lecture seule de façon fiable d'un passage à l'autre, abandonné.

Le nom de zone refusé pour un caractère invisible répond `invalid_label` (« Donnez un nom au lieu. ») : aucun code ni
texte nouveau, pour rester dans le périmètre de la relecture.

**Essais hors jeu** (Node 24, fichiers de brouillon du dossier temporaire de la session, jamais un vrai `server.cfg`),
quatre passages identiques, 11 essais :
1. fichier ANSI (Windows-1252, accent) : `encoding`, octets intacts, aucune sauvegarde, pas retenté ;
2. BOM et CRLF, accents UTF-8 : BOM unique en tête, CRLF partout, sauvegarde égale à l'ancien contenu, seconde passe vide ;
3. fins de ligne mélangées (`\r\n`, `\n`) : chaque ligne garde la sienne, le bloc prend celle de sa voisine ;
4. `exec voice.cfg` : rien d'écrit, avertissement « ligne 2 », pas retenté ; `# exec` en commentaire ignoré ;
5. `;` : deux `setr` sur une ligne → rien d'écrit ; `ensure a; exec voice.cfg` → `exec` vu ; `;` entre guillemets
   (chaîne MySQL) et `;` qui ne touche pas la voix → complété normalement ;
6. `set` au lieu de `setr` : pas de doublon, avertissement, l'autre réglage ajouté, jamais réajouté ; `sets` et convar
   nue signalés ; `setr … false` gardé ;
7. lecture seule : `EPERM`, rien d'écrit, ni temporaire ni sauvegarde, pas retenté (même droit rendu, fichier
   inchangé), complété dès que le fichier change ;
8. échec simulé du renommage : temporaire et sauvegarde du tour retirés, sauvegardes existantes intactes ;
9. lien symbolique de fichier : non essayé (droit de créer des liens absent sur cette machine Windows) ; jonction de
   dossier à la place : chemin réel écrit, jonction gardée, aucun temporaire ;
10. `write` d'un fichier neuf : écrit, pas de sauvegarde, aucun temporaire (droits `0640` repris : essai POSIX, non
    joué sous Windows) ;
11. assistant : rien en double, `setr … false` des options avancées gardé.

`node --check` sur `index.js`, `lib/servercfg.js`, `lib/process.js`, `lib/config.js`, `web/js/strings.js` et
`node index.js --verifier` : OK.
