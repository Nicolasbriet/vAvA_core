# T-133 — `%c` dépend de la locale : contrôles de texte justes partout

Pas de spec (tâche de correctif). Procédures en jeu : `docs/tests/chat.md` 6-12, `docs/tests/personnage.md` 2-14,
`docs/tests/metiers.md` 4-8b, `docs/tests/atelier.md` 5-4, `docs/tests/inventaire.md` 10-3b.

Les classes de motifs de Lua (`%c`, `%s`, `%a`, `%w`, `%l`, `%u`, `%p`, `%g`, `%d`) et `string.lower` / `upper`
suivent la locale C du processus. Relevé sous une locale Windows à octet unique (cp1252), octets 0x80 à 0xFF :
`%c` prend 0x81, 0x8D, 0x8F, 0x90, 0x9D, 0xAD (octets de suite de « Á », « Í », « Ï », « Ð », « Ý », « í », U+2010) ;
`%s` prend 0xA0 (fin de « à », « Š », « Ġ », de l'espace insécable) ; `%d` prend 0xB2, 0xB3, 0xB9 ; `%a`, `%w`, `%l`,
`%u`, `%p`, `%g` prennent la plupart des octets ; `string.lower` change 0xC3 en 0xE3 (UTF-8 cassé). Sous la locale
« C », rien de tout cela. La locale réelle de FXServer sous Windows n'est pas connue : le correctif rend le code juste
dans les deux cas.

## Relecture sécurité (vava-securite) : À CORRIGER, corrigé

- IMPORTANT, `str.sanitize` : l'ancien `%c` retirait par accident, sous cp1252, une partie des contrôles C1 écrits en
  UTF-8 ; avec `[\0-\31\127]` seul, CSI (U+009B), OSC (U+009D), DCS (U+0090)… passaient intacts jusqu'à la console
  (`server/core/rpc.lua:164` recopie un nom de RPC inconnu ; une console xterm.js ou txAdmin les interpréterait).
  **Corrigé** : liste commune au core (`CONTROL_SEQUENCES`, `str.hasControl`) alignée sur `vava_atelier` (ASCII, C1,
  U+200B à U+200F, U+2028 à U+202E, U+2066 à U+2069, U+061C, U+FEFF), chaque séquence remplacée par une espace dans
  `sanitize`. L'Atelier garde sa propre liste (il ne dépend pas du core pour cela) ; les deux couvrent la même chose.
  Essais : U+0080 à U+009F et marques remplacés, U+00A0 à U+017F intacts.
- MINEUR 2, essais qui passaient avec l'ancien code sous la locale « C » : **corrigé** par `helper.legacyLocale` dans
  les quatre fichiers d'essai concernés ; contrôle du `%c` ajouté à `scripts/audit-reseau.sh` (plus simple et moins
  fragile qu'un essai qui listerait les fichiers depuis le lanceur).
- MINEUR 3, motifs d'identifiants (`[%w_]`, `[%l%d_]`…) trop permissifs sous cp1252 : **non corrigé ici**, à la
  demande du coordinateur (défense en profondeur, aucun risque trouvé) ; ajouté au backlog par lui.
- MINEUR 4, recherche du catalogue (`vava_inventory/server/catalog.lua`) : **corrigé** (repli puis casse ASCII).
  Fonction locale d'un fichier serveur : pas d'essai unitaire, procédure inventaire 10-3b.
- MINEUR 5, `foldName` des personnages : **corrigé** (`str.asciiLower`, même résultat avec la config par défaut).
- MINEUR 6, clé de l'exemple : **corrigé** (`’`, `ß`, paires de casse du latin étendu, `İ`) ; l'exemple n'a pas accès
  à la normalisation de l'Atelier (autre ressource), la table est donc la sienne.
