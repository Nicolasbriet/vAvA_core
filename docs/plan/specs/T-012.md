## 1. But joueur

À sa première connexion, un joueur télécharge environ 4,2 Mo de fichiers d'interface, dont plus des deux tiers sont les
mêmes polices et textures copiées quinze fois. Après T-012, il ne les télécharge qu'une fois (environ 1,3 Mo en tout) :
il arrive plus vite dans le royaume, et toutes les interfaces gardent exactement la même allure.

Pilier du lore : « On y vient pour recommencer » (l'arrivée d'un nouveau joueur est un moment soigné : moins d'attente
avant le premier écran). Pas de nouvelle mécanique.

## 5. Données

Aucune table SQL, aucun champ de personnage, aucune métadonnée d'objet.

**Textures en WebP.** Le CEF de FiveM est un Chromium (WebP lu depuis Chrome 23) : format sûr, à confirmer en jeu
(§ 14). Conversion faite une fois, hors dépôt, sans ajouter d'outil au dépôt : `cwebp` de libwebp s'il est présent,
sinon encodage par un `canvas` dans Edge sans fenêtre (`toDataURL('image/webp', 1)` = sans perte). Ordre d'essai :
1. **sans perte** (`cwebp -lossless -exact -z 9`) : aucun risque de raccord visible quand la texture se répète ;
2. si le gain est inférieur à 20 %, **avec perte** `-q 90 -alpha_q 100` et contrôle des raccords (§ 11, planche
   `apercu.html` en grand, tuiles côte à côte) ;
3. si aucune version ne gagne 20 % sans différence visible, garder le PNG dans `vava_ui` (`web/img/*.png` ajouté aux
   `files`, jeton qui pointe vers le PNG) et l'écrire au rapport.
Les deux tailles (PNG, WebP retenu, réglage) vont au rapport. Le canal alpha est gardé (le grain se pose sur des
dégradés).

Poids attendu de `vava_ui` livré : 148 084 o de polices + environ 1,7 Ko d'ornements + environ 3 Ko de feuille + les
textures (95 373 o en PNG ; attendu 45 à 70 Ko en WebP) : **environ 200 à 225 Ko**.

**Méthode de mesure** (la même avant et après, à lancer à la racine du dépôt dans Git Bash ; résultat par ressource et
total au rapport) :

```bash
# poids livré = fichiers cités par `files { … }` de chaque fxmanifest (motifs d'un niveau, comme FXServer)
poids() {
  ( cd "$1" && sed -n '/^files[[:space:]]*{/,/^}/p' fxmanifest.lua | grep -oE "'[^']+'" | tr -d "'" |
      while read -r motif; do for f in $motif; do [[ -f "$f" ]] && stat -c %s "$f"; done; done
  ) | awk '{ s += $1 } END { print s + 0 }'
}
for r in modules/*/ examples/vava_example_items/; do printf '%s\t%s\n' "$(poids "$r")" "$r"; done | sort -rn
for r in modules/*/ examples/vava_example_items/; do poids "$r"; done | awk '{ s += $1 } END { print "total", s }'
# copies restantes (empreintes identiques dans plusieurs ressources) :
git ls-files 'modules/*/web/*' | xargs sha1sum | sort | uniq -w40 --all-repeated=separate
```

Après T-012, la dernière commande ne doit montrer **aucune** police, texture ni ornement ; d'éventuelles images
d'objets identiques entre deux modules sont notées au rapport pour information (hors critère).

**Forme des adresses.** `nui://<ressource>/<chemin>` est la forme qu'emploie déjà le dépôt entre ressources (images des
objets d'autres modules dans l'inventaire, icônes de `vava_needs` dans le HUD, `docs/api.md` l. 540 et 744), validée
en jeu à la porte T-009 pour des **images**. Il suffit que le fichier soit cité par `files` de la ressource qui le
sert, démarrée (`vava_needs` le fait sans `ui_page` : même cas que `vava_ui`). Une **feuille** et des **images**
chargées depuis une autre origine n'ont besoin d'aucune autorisation ; une **police**, si (le navigateur la demande en
mode CORS). C'est le seul point que le dépôt n'a jamais vérifié : premier test en jeu (§ 14), avec son échelle de
repli (§ 12).

## 7. Vérifications serveur

Aucune : rien n'entre par le réseau, rien n'est décidé. Ce que le serveur garantit est l'**ordre de démarrage** :
- `vava_ui` ne dépend de rien et démarre juste après `vAvA_core`, avant `vava_chat` (première ressource à page) ;
- chacun des 15 modules déclare `dependency 'vava_ui'` : FXServer refuse de le démarrer si `vava_ui` manque, et

  nouvelle version s'applique au redémarrage du serveur (ce que fait la Chancellerie). Voir « Décisions à confirmer » 1.

## 8. Client

Aucun fichier Lua, aucune boucle, aucun prop, aucun `SendNUIMessage` : rien au resmon.

Chargement d'une page en jeu : sa feuille `vava_ui.css` (environ 3 Ko, une requête locale au cache de FiveM), puis les
seules polices et textures qu'elle emploie. Les 15 pages lisent les mêmes fichiers, servis une seule fois depuis le
cache du client.

**Si `vava_ui` manque côté client** (cas anormal : fichier absent du cache, ressource arrêtée à la main), dégradation
**voulue et lisible** :
- polices : chaque pile de polices des modules finit déjà par `"Palatino Linotype", Georgia, serif` ;
- textures et ornements : chaque emploi est écrit `var(--ui-…, none)` ; sans la feuille, le jeton n'existe pas et
  l'image devient `none` : les dégradés du cuir et du parchemin restent, seuls le grain, le papier et les coins de
  laiton disparaissent. Aucun panneau ne devient transparent ni illisible. (Sans le `, none`, toute la déclaration
  `background` serait invalide et le panneau perdrait aussi ses dégradés : le repli est obligatoire.)

- Les adresses que les devmocks construisent (`../../vava_needs/web/icons/…`, `../../../examples/…`) sont relatives à

**`vava_ui/web/dev/horsjeu.js`** (jamais livré ; ne fait rien en jeu) :

```js
'use strict';
/*
 * vava_ui/web/dev/horsjeu.js
 * Rôle : hors jeu seulement (page ouverte dans un navigateur depuis le dépôt) : la feuille commune et les textures de
 *        vava_ui sont prises dans le dépôt au lieu de nui://vava_ui/, que le navigateur ne connaît pas. Jamais livré
 *        (absent des `files` de vava_ui), jamais chargé en jeu.
 */
(() => {
  if (typeof GetParentResourceName === 'function') return;
  const PREFIX = 'nui://vava_ui/';
  const ROOT = new URL('../../', document.currentScript.src).href; // …/modules/vava_ui/
  document.querySelectorAll(`link[rel="stylesheet"][href^="${PREFIX}"]`).forEach((link) => {
    link.href = ROOT + link.getAttribute('href').slice(PREFIX.length);
  });
  // mêmes jetons que web/css/vava_ui.css (tenus ensemble : tests/spec/ui_shared_spec.lua le vérifie)
  const TEXTURES = { '--ui-grain': 'web/img/grain.webp', '--ui-paper': 'web/img/paper.webp',
    '--ui-frame': 'web/img/frame.svg', '--ui-divider': 'web/img/divider.svg', '--ui-diamond': 'web/img/diamond.svg' };
  for (const [name, file] of Object.entries(TEXTURES)) {
    document.documentElement.style.setProperty(name, `url("${ROOT}${file}")`);
  }
})();
```

5. **Jetons communs** : `vava_ui.css` porte les couleurs des fonds clairs et sombres de `CLAUDE.md` (`--ui-*`), mais
